# 9/13 方針決定のための実測実験 仕様

Status: 実装・実行依頼
Date: 2026-09-06
納期: 9/12まで(9/13の3人会議に持ち込む)
背景: 9/5のテストプレイ(付喪神×京鬼ミラー、人間2名)の結果、チームは「召喚1体制限に戻す(案1)」と「複数召喚で進む(案2)」の分岐に立っている。**案1は8/28改訂と組んだ挙動が一度も測られていない**とチーム側が明記しており、その空白を埋めるのが本実験の主目的。

## 0. 9/5テストプレイで観測された事実(実装の動機)

複数召喚ルールで人間が対戦した結果:

1. **攻撃が割に合わない** — 原因が4つ重なっている
   - HP分は倒されると半分戻るが、攻撃コストは戻らない
   - 反撃が無料。先に攻撃した側の霊力効率が下がる
   - 倒すと相手に霊力を与えてしまう(被撃破半額還付)
   - **攻撃してもマスが増えない**(勝利条件に寄与しない)
   - 実際、片方は自発的な攻撃をほとんど選ばなかった
2. **高コスト式神が死に札** — 複数召喚だと霊力を使い切れるので余剰が小型2枚に流れ、霊力が貯まらない。召6〜7は「早いと邪魔、中盤以降は出す霊力がない」
3. **範囲攻撃が機能しない** — 味方巻き込みのため低コスト並べへのカウンターにならず、振る機会が来ない。範囲での反撃は卓上の処理負荷が大きい

**注意**: 8/23の外部テスト会では全員が攻撃したがっていた。緩めすぎると8/23以前の症状(殴り合いで盤面HPが減り続け、制圧に到達しない)が再発しうる。

## 1. 実装するconfigフラグ

すべて `Config` に追加し、CLIから `--flag value` で指定できるようにする。**既定値は現行挙動と完全一致**させ、既存テストが無改変で通ること。

| フラグ | 型 / 値 | 既定 | 意味 |
|---|---|---|---|
| `summonLimit` | number \| null | `null` | 1ターンに召喚できる体数。`null`=無制限、`1`=1体制限。**メインフェイズは召喚後も継続する**(「召喚したらフェイズ終了」は8/28で撤廃済み、案1でも戻さない) |
| `aoeMode` | `"on"` \| `"off"` \| `"no_ff"` | `"on"` | `off`=AoEカードを単体攻撃として扱う(範囲内の敵1体を選択)。`no_ff`=範囲内の**敵のみ**に命中(味方に当たらない) |
| `counterMode` | `"all"` \| `"single"` | `"all"` | `single`=1回の攻撃に対する反撃は**攻撃者を攻撃範囲に収めている敵のうち1体のみ**(複数該当時は実効HPが最大の1体)。範囲反撃の処理負荷解消が目的 |
| `attackCostDelta` | number | `0` | 全カードの攻撃コストに加算(下限1)。`-1`で一律1安くなる |
| `refundMode` | `"half"` \| `"none"` | `"half"` | `none`=被撃破時の霊力還付をなくす |
| `summonCostScale` | `"full"` \| `"half"` | `"full"` | `half`=召喚コストを `ceil(summonCost/2)` にする(下限1)。`refundMode:"none"` とセットで使う想定 |
| `moveOnKill` | boolean | `false` | `true`=攻撃で敵を撃破したとき、攻撃者を**そのマスへ移動**させる(向きは変えない)。複数体を同時撃破した場合は移動しない。AoEでも同様に不発。移動先の属性でHP再計算が起きる。**移動により実効HPが0以下になる場合は移動しない** |
| `lifeValueEnabled` | boolean | `true` | `false`=生命価による生命減少を廃止し、**生命0による敗北も廃止**(撃破勝利の廃止) |
| `deckOutMode` | `"none"` \| `"second"` | `"none"` | `second`=**2度目のデッキ切れ**(墓地シャッフルが2回発生)が起きた時点でゲーム終了。そのとき占拠マス数が多い方の勝ち、同数なら引き分け |
| `incomeTiming` | `"turn_start"` \| `"turn_end"` | `"turn_start"` | `turn_end`=霊力獲得を自分のターン終了時に移す(手札整理と同じタイミング。制圧判定→霊力獲得→手札整理の順) |
| `baseIncome` | number | `3` | 既存。実験で変更する |

### 実装上の注意

- `moveOnKill` は combat.ts の撃破解決の**後**、反撃解決の**前**に処理する(移動してから反撃を受ける)。ただし攻撃者が反撃で撃破されうる点は変えない
- `deckOutMode:"second"` の判定は、`PlayerState` に `reshuffleCount` を持たせて墓地シャッフル時にインクリメントし、**どちらかが2に達した時点**で終了。`winType` に `"deck_out"` を追加。引き分けは `winner: null, winType: "deck_out"`
- `lifeValueEnabled:false` のとき、AIの評価関数から life 項を除く(`W.life` を0扱い)。そうしないと存在しない勝ち筋を追う
- `summonLimit` はAIの合法手列挙で自然に効くこと(その turn の召喚回数を `GameState` に持たせる)

## 2. 実験メニュー

すべて **pack-tsukumo-miyako のミラー、chipMode=catch_up、effects=on、seed 20260906 から連番、AIは greedy と beam の両方**。試合数は greedy 100 / beam 50。

### A群: 案1(召喚1体制限)の実測 ← **最優先。これが本実験の主目的**

チーム側が「一度も測られていない」と明記した空白。8/28改訂(チップ/攻撃コスト分離/太極−2/1ターン保持/被撃破半額)を**すべて載せたまま**召喚数だけ1に戻したとき、8/23の病が消えているかを見る。

| # | summonLimit | aoeMode | incomeTiming | 備考 |
|---|---|---|---|---|
| A0 | null | on | turn_start | **現行(対照)** = 8/30測定の再現 |
| A1 | **1** | on | **turn_end** | 案1・範囲そのまま |
| A2 | **1** | **off** | **turn_end** | 案1・範囲を単体化(「範囲攻撃をなくす」) |
| A3 | **1** | **no_ff** | **turn_end** | 案1・範囲は残すがFF撤廃 |

**A群で最重要の観測項目**(8/23の病が消えたかの判定):

- **制圧決着率**(8/23は0%だった。目標は高いこと)
- **盤面の実効HP合計の推移**(減り続けるか、維持されるか) ← 新規メトリクス
- **高コスト式神(召5以上)の召喚率と、召喚された平均ラウンド** ← 新規メトリクス。「死に札」問題が1体制限で解消するかの直接測定
- **ターン終了時の余剰霊力の平均** ← 新規メトリクス。「余剰霊力が貯まって高コストが出る」という推定の検証
- 攻撃回数/試合、平均ラウンド、先手勝率

### B群: 案2の対応案(問題1〜3への処方を1つずつ)

**まとめて入れず、1つずつ測る**(チーム側の方針と同じ)。すべて summonLimit=null(複数召喚)。

| # | 変更 | 狙う問題 |
|---|---|---|
| B0 | なし(=A0と同じ) | 対照 |
| B1 | `attackCostDelta: -1` | 【1】攻撃が重い |
| B2 | `counterMode: "single"` | 【1】反撃が無料 + 処理負荷 |
| B3 | `refundMode:"none"` + `summonCostScale:"half"` | 【1】倒すと相手が潤う / 【2】高コストが出せない |
| B4 | `moveOnKill: true` | 【1】**攻撃してもマスが増えない**(構造) |
| B5 | `aoeMode: "no_ff"` | 【3】範囲がFFで死んでいる |
| B6 | `baseIncome: 4` | 【2】霊力不足で高コストが出ない |

**B群で最重要の観測項目**: 攻撃回数/試合(B0比で増えたか)、高コスト召喚率、制圧決着率、平均ラウンド、先手勝率。

### C群: 分岐と独立の決定事項の検証

| # | 変更 | 見たいこと |
|---|---|---|
| C1 | `lifeValueEnabled:false` + `deckOutMode:"second"` (複数召喚) | 2度目のデッキ切れに**到達するか**。引き分けは出るか |
| C2 | 同上 + `summonLimit:1` | 1体制限では試合が伸びるため、到達しうる。到達率と引き分け率 |

**C群で最重要**: 決着種別の内訳(制圧 / デッキ切れ判定 / 引き分け / ラウンド上限)、平均ラウンド。
