## 0. 実装方針(確定済み)

- DSL化は不要。`src/effects.ts` 1モジュールに cardId ベースのフック実装でよい
- フック点の目安: onTurnStart / modifyAttackDamage / onAfterAttack / onSummon / onUnitDestroyed / canRotateCommand / rotateCommandRedirect / 霊具アクション
- CLIに `--effects on|off`(既定 on)。**off で従来挙動と完全一致**(既存56テストが全通過することで担保)
- 霊具はアトミックアクション: コスト支払い → 効果解決 → 墓地。**1ターンの使用回数制限なし**(霊力のみが制約)。greedy/beam の候補列挙に追加
- UIにも霊具使用と効果発動ログを反映
- 各効果に受け入れテスト最低1件(tm04の死文化はテスト不要)

## 3. 競合・解決順

- 同一攻撃に複数のダメージ修正(例: 影鬼の+1と死角+2、提灯の+1)は**すべて加算**
- 照魔鏡のATK参照と一目鬼の巨撃が両立する状況は現デッキでは発生しない(別カード)。将来のため: **ATKの置換(照魔鏡)を先に解決し、その後に加算修正**
- マヨヒガ対象のユニットは: 攻撃対象に選べない / AoEにも当たらない / 霊具の対象に選べない / 占拠・リーチ・チップの計算から除外 / 自身はコマンド不可(命令の対象にならないため)。**盤面のマスは物理的に塞いだまま**(そのマスへは召喚できない)
- 玖龍街が複数(ミラーで両者が出した)場合: 双方が回転コマンド不可。各自の玖龍街の代理回転は可(それは「効果」側の扱い)
- 効果によるHP増加はすべて「実効最大まで」(鬼の酒のみ例外で7固定・上限10)
