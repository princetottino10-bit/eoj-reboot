# sim2 対戦画面 v2 — ゲームらしい画面と「その場で変えられる変数」 設計書

Status: 設計確定(実装待ち)
Date: 2026-09-13
設計: Fable / 実装: Opus
対象: `sim2/play/`(人間 vs AI)と `sim2/online/`(人間どうし)。描画は両者で共有している `play/table.ts` / `play/render.ts` / `play/table.css` を作り直す

---

## 0. 目的

1. **テストプレイの道具から、遊んでいて気分の上がる対戦画面へ。** 今の画面は表計算ソフトのように情報を並べただけで、何が起きたかが目で追えない
2. **ルールの数値やカードの数値を、その場で変えて試せるようにする。** チームは毎回「収入を4にしたら」「子鬼のHPを3にしたら」を議論している。コードを触らずに画面から変えて、すぐ遊べるようにする

**やらないこと**: ルール判定をブラウザに持ち込むこと。変数を変えても、判定は常にサーバー(ローカル対戦ではエンジン)が行う。

## 1. 見た目の方向性: 「夜の陰陽寮、漆と金箔の盤」

一言でいうと、**夜の卓上に置かれた漆塗りの九宮盤と、墨と金で描かれた札**。和風のテンプレート的な装飾(桜・赤い鳥居の多用)には寄せない。静かで、重みがあり、要所だけ光る。

### 1.1 配色(CSS変数で定義し、ハードコードしない)

| 役割 | 変数 | 値の目安 | 用途 |
|---|---|---|---|
| 背景 | `--bg` | 墨に近い藍 `oklch(18% 0.02 260)` | 画面全体。**わずかに紙の粒子**(CSSのノイズ風グラデーション)を重ねる |
| 盤 | `--board` | 漆黒 `oklch(14% 0.01 30)` | 九宮盤の地。縁に**細い金線** |
| 金 | `--gold` | `oklch(80% 0.12 85)` | 枠線・強調・勝敗の演出だけに使う。多用しない |
| 陰マス | `--yin` | 青みの墨 `oklch(32% 0.05 260)` | |
| 陽マス | `--yang` | 朱を抑えた暖色 `oklch(42% 0.08 50)` | |
| 太極 | `--taiji` | 盤と同色の地に**陰陽の渦の意匠**を薄く | |
| 空マス | `--void` | 盤よりわずかに明るい | |
| 先手の色 | `--p0` | 群青 `oklch(62% 0.13 250)` | 自分の駒の縁・名札 |
| 後手の色 | `--p1` | 朱 `oklch(62% 0.16 30)` | |
| 札の地 | `--card` | 生成りの和紙 `oklch(92% 0.02 85)` | 手札と盤上の駒の地 |
| 文字 | `--ink` | 墨 `oklch(20% 0.01 260)` | 札の上の文字 |

**色覚への配慮**: 先手・後手を色だけで区別しない。駒の縁の形(先手は角、後手は丸)または名札の記号も併用する。攻撃範囲・死角・隙位置も、色に加えて線種(実線・破線・斜線)で区別する。

### 1.2 文字

- 見出し・札の名前: **Shippori Mincho B1** または **Zen Old Mincho**(Google Fonts)。読み込めない環境のために `serif` 系のフォールバックを必ず書く
- 数値(HP・ATK・霊力): 等幅で読みやすい書体(`font-variant-numeric: tabular-nums`)
- 本文・ログ: **Zen Kaku Gothic New** + `sans-serif` フォールバック
- 外部依存ゼロの原則との関係: **フォントの `<link>` だけは許可する**(ビルド依存ではなく、読み込めなくても表示が崩れないため)。それ以外のCDN・ライブラリは入れない

### 1.3 画面の構成(横長画面・1280px以上を基準)

```
┌──────────────────────────────────────────────┐
│ [相手の名札: 生命 霊力 チップ 占拠] [相手の手札 裏向き扇形]    │
├───────────┬──────────────────────┬───────────┤
│ 相手の     │                          │ 手番表示     │
│ 山札・墓地  │        九宮盤(中央・大)     │ ログ(折畳可)  │
│           │                          │ 選択中の札の  │
│ 自分の     │                          │ 詳細(大きく)  │
│ 山札・墓地  │                          │             │
├───────────┴──────────────────────┴───────────┤
│ [自分の名札] [自分の手札 表向き扇形。選ぶと持ち上がる] [ターン終了] │
└──────────────────────────────────────────────┘
```

- **盤が主役**。画面の高さの6割以上を盤に使う
- 手札は画面下に**扇形**に並べ、カーソルを乗せると持ち上がり、選ぶとさらに持ち上がる
- 相手の手札は画面上に**裏向きの札**として枚数分並べる
- ログは右側。**既定では直近5件だけ表示**し、展開で全件
- 1024px幅でも崩れない(右側の列を盤の下に回す)。スマホ最適化はしない

### 1.4 札(カード)のデザイン

札は手札と盤上で**同じ意匠**を使い、盤上では小さく、手札では大きく、選択中の詳細欄ではさらに大きく表示する。

```
┌────────────────┐
│ 召3        陰 ●  │ ← 左上に召喚コスト(円の中)、右上に属性の印
│                  │
│      鎖          │ ← イラストの代わりに、名前の1文字目を大きく墨書き風に
│                  │    (一門ごとに地の模様を変える: 酒呑=波、玖龍街=格子、など)
│ 鎖鬼              │ ← 名前
│ ┌─┬─┬─┐          │
│ │ │■│ │  範囲    │ ← 攻撃範囲の小図(死角・隙位置も記号で)
│ └─┴─┴─┘          │
│ 攻2    HP 3  ATK 2│ ← 下段に攻撃コストとHP・ATK
│ 効果テキスト(手札・詳細のみ)│
└────────────────┘
```

**盤上の駒**は札を縮小したもの:
- 札の上端に**向きを示す金の矢じり**。回転したら札ごと回るのではなく、矢じりが回る(文字が逆さにならないように)
- HPは札の下に**数字+細いゲージ**。ダメージを受けた分は赤く削れる
- 攻撃済み・回転済みは、札を**わずかに暗く**して右下に小さな印
- 制圧状態の側の駒は、盤の縁ごと**金色の光がゆっくり脈打つ**
- マヨヒガで隠された駒は**半透明の霧**をかぶせる

### 1.5 動き(演出)

`transform` と `opacity` だけを動かす(レイアウトを揺らさない)。`prefers-reduced-motion` のときは全部オフにする。

| 場面 | 演出 | 時間 |
|---|---|---|
| 召喚 | 札が手札から盤のマスへ飛び、着地で軽く沈む。着地点に波紋 | 350ms |
| 継承召喚 | 元の札が墨のように溶け、新しい札が浮かび上がる | 450ms |
| 攻撃 | 攻撃者が対象の方向へ**一瞬踏み込み**、対象が揺れる。ダメージ数字が浮かんで消える | 400ms |
| 死角攻撃 | 上に加えて、対象の背後に**金の閃光**と「死角」の文字 | +200ms |
| 反撃 | 対象から攻撃者へ逆向きの踏み込み。「反撃」の小さな文字 | 300ms |
| 撃破 | 札が割れて(2つに裂けて)沈む。持ち主の生命が減る数字を名札で強調 | 500ms |
| 霊力の増減 | 名札の霊力の数字が弾む。増えたら金、減ったら灰 | 250ms |
| チップ獲得 | チップの印が1つずつ灯る | 300ms/枚 |
| 回転 | 矢じりが回る | 200ms |
| 手番交代 | 画面中央に「先手の番」「後手の番」の帯が左から右へ流れる | 700ms |
| 制圧状態に入る | 盤の縁の金線が一周光る+帯「制圧」 | 800ms |
| 決着 | 盤全体が暗くなり、中央に大きく「勝」「敗」を墨書き風に。「もう一戦」ボタン | — |

**演出中も操作は受け付ける**(演出を待たせない)。AIの手番と相手の手番は、1手ごとに演出が終わってから次を見せる。

### 1.6 操作の分かりやすさ

- **合法手だけが光る**。手札の札を選ぶと、置けるマスが淡く光り、継承できる自分の駒は**紫の破線**で光る
- 自分の駒を選ぶと、その駒の周りに**丸いメニュー**(攻撃・回転左・回転右・渾身・回復・代理回転)を出す。使えないものは暗くして、理由をツールチップで出す(「霊力が足りない(あと1)」「攻撃済み」「玖龍街により回転不可」)
- 攻撃対象を選ぶと、**確定前に予測を盤上に重ねて表示**: 与えるダメージ・撃破するか・反撃があるか・反撃ダメージ。今の予測表示(テキスト)をこの形に置き換える
- 霊力が足りない操作のコストは赤く、足りる操作は金で表示
- キーボード: `Esc` で選択解除、`Enter` でターン終了確認、`Z` で直前の選択を取り消し(確定済みの手は戻さない)

## 2. その場で変えられる変数

### 2.1 何を変えられるか

**ルールの変数**(`Config` の全項目のうち、遊びに関わるもの)と、**カードの数値**。

| 区分 | 変数 | 入力の形 |
|---|---|---|
| 霊力 | 初期霊力(先手・後手)/ 毎ターン収入 / 霊力上限 / 収入のタイミング | 数値 / 選択 |
| チップ | 獲得方式 / 段(何枚目で+1か) | 選択 / 数値の並び |
| 盤 | 太極の軽減 / 太極の下限 / 属性ボーナス / 死角ボーナス / 最大HP | 数値 |
| 行動 | 回転コスト / 攻撃コストの増減 / 1ターンの召喚上限(なし・1・2…) | 数値 |
| 戦闘 | 反撃方式 / 範囲攻撃の味方巻き込み / 撃破時の霊力の受け取り方 / 召喚コスト半額 | 選択 / オンオフ |
| 勝敗 | 制圧に必要なマス数 / 制圧の保持判定 / 生命価のオンオフ / 初期生命 / デッキ切れ判定 / ラウンド上限 | 数値 / 選択 / オンオフ |
| 手札 | 補充枚数 / 補充方式 / マリガン | 数値 / 選択 / オンオフ |
| 特殊 | 継承召喚 / 撃破時に移動 / カード効果 | オンオフ |
| **カード** | パック内の各カードの **召喚コスト・攻撃コスト・HP・ATK・生命価** | 数値(表形式) |

各変数には**日本語の名前と一行の説明**を付ける(`src/presets.ts` 付近に `CONFIG_SCHEMA` として1箇所に定義し、画面はこれを読んで入力欄を自動生成する)。範囲外の値(負の霊力、HP0など)は**サーバーで拒否**する。

### 2.2 いつ変えられるか

| タイミング | ルールの変数 | カードの数値 | 誰が |
|---|---|---|---|
| **部屋を作るとき** | ○ | ○ | 部屋を作った人 |
| **試合と試合の間**(「もう一戦」の前) | ○ | ○ | 部屋を作った人。変更点が両者に表示され、**相手の同意ボタン**で次の試合に反映 |
| **試合の途中** | ○(**一部を除く**) | × | 部屋を作った人が提案 → **相手の同意で即反映**。ログに「ルール変更: 収入 3→4」と残る |
| ローカルのAI対戦 | いつでも○ | 試合の間のみ○ | 自分 |

**試合の途中で変えられない変数**(変えると状態が壊れるもの): 初期霊力・初期生命・盤のマス数・マリガン・カードの数値。これらは画面上で「次の試合から」と表示して入力できないようにする。

**試合の途中で変えた場合の扱い**:
- 変更は**次の操作から**有効(過去の結果は変えない)
- 最大HPや属性ボーナスを変えたとき、盤上の駒の現在HPは「最大HPが下がったら現在HPも上限で切る」「上がっても現在HPは増やさない」
- 棋譜には変更を**入力の1つとして記録**し、再生すると同じ結果になること(既存の決定性の保証を維持)

### 2.3 保存と共有

- よく使う設定を**名前を付けて保存**(ブラウザの `localStorage`)
- **設定をURLに埋め込んで共有**できる(「この設定で遊んで」とLINEで送れる)。URLが長くなりすぎる場合は、既定値との差分だけを埋め込む
- 9/13テストルール・8/28ルールは**変更できない基準プリセット**として残し、「ここから変える」形にする
- 画面の上部に、**基準プリセットから変えている項目の数**を常に表示する(「9/13ルール +3項目変更」)。押すと差分の一覧。テストの記録で「どの設定で遊んだか」を取り違えないため

### 2.4 設定画面の見た目

- 部屋作成・試合間・ローカル対戦の設定は、同じ**設定パネル**を使う
- 設定パネルはダイアログではなく**設定ページ `/rules`** に置く(画面全体を使い、文書ごとスクロールし、区分のタブと下のボタン列は固定)。
  開き方は URL で決まり(`?for=ai` / `lobby` / `ai-game` / `room&code=`)、「戻る」とブラウザの戻るで元の画面へ。
  対AIの対局は入力をブラウザに保存しているので、ページを行き来しても同じ対局が続く
- 変数は区分ごとに折りたたみ。**既定値から変えた項目は金色の印**
- 数値は `−` `+` ボタンと直接入力の両方
- カードの数値は**表**で、パックの全カードを並べ、変えたセルは金色
- 「すべて基準に戻す」「この区分だけ戻す」

## 3. 実装方針

- 描画の共有部品(`play/table.ts` / `play/render.ts` / `play/table.css`)を作り直し、ローカル対戦とオンライン対戦の**両方が同じ見た目**になる
- 演出は「状態の差分」ではなく**エンジンのイベント列**から作る(既に `GameEvent` が出ている)。イベントを順に再生するキューを1つ作り、演出の時間だけ待ってから次を描く
- **ルール判定をブラウザに書かない**。合法手・攻撃予測はサーバー(ローカルではエンジン)から受け取る。攻撃予測が今ブラウザ側で計算されているならサーバー側に移す
- カードの数値の上書きは、**パックを複製して値を差し替えたものを Ctx に渡す**形にする(元のパックJSONは変更しない)
- `CONFIG_SCHEMA` は、CLI(`--help` の説明)・ローカル対戦・オンライン対戦で共通
- 画像ファイルは使わない(札の意匠はCSSとSVGで描く)。SVGはインラインで持つ

## 4. 受け入れ条件

### 4.1 テスト(`node:test`)

1. `CONFIG_SCHEMA` の全項目に日本語名・説明・型・範囲があり、`Config` の遊びに関わる全フィールドを網羅している
2. 範囲外の値を含む設定での部屋作成・途中変更は拒否される
3. 試合途中に変更できない変数の変更提案は拒否される
4. 途中変更は**相手の同意があるまで反映されない**。同意後は次の操作から有効
5. 途中変更を含む棋譜を再生すると、同じ結果になる
6. カードの数値の上書きが試合に反映され、**元のパックデータは変わらない**
7. 設定のURL埋め込み→復元で同じ設定になる
8. 隠し情報のテスト(既存)が引き続き通る。**変更提案・同意のメッセージ経由で隠し情報が漏れない**
9. 既存のテスト(161件)がすべて通る

### 4.2 画面の確認(ブラウザで実際に操作する)

以下を実際に通し、**スクリーンショットを `sim2/out/ui-v2/` に保存**する。

1. ローカル対戦: 9/13ルールで1試合を最後まで。召喚・攻撃・死角攻撃・反撃・撃破・継承召喚・マリガン・制圧状態・決着の演出がそれぞれ出る
2. オンライン対戦: 2つのタブで部屋作成→参加→途中で「収入 3→4」を提案→相手が同意→反映をログで確認→決着→設定を変えて「もう一戦」
3. カードの数値を変えた部屋で、変えた値が札に表示され、戦闘結果に反映される
4. 1280px と 1024px の2つの幅で崩れない
5. `prefers-reduced-motion` で演出が止まる

## 6. 非スコープ

- カードのイラスト(チームの絵が決まったら差し替えられるよう、札の中央の領域を1箇所で差し替え可能にしておくだけ)
- 効果音・BGM
- スマホ向けレイアウト
- 新しいカード効果の追加(数値の変更のみ。効果の文面を画面から作ることはしない)
